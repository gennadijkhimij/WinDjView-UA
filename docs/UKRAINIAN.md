# Українська локалізація WinDjView 2.1

Повний переклад інтерфейсу WinDjView 2.1 українською мовою та інсталятори. Ця гілка (`main`) — це репозиторій [raspopov/WinDjView](https://github.com/raspopov/WinDjView) (конвертований з CVS SourceForge, історія збережена) плюс зміни, описані нижче. Код самої програми **не змінено**.

## Для користувачів

Готові файли беруть зі сторінки **Releases** цього репозиторію:

| Файл | Що робить |
|---|---|
| `WinDjView-2.1-Setup.exe` | Повний інсталятор: програма (64-бітна) + українська мова. Інтерфейс інсталятора — українська/англійська. Тихе встановлення: `/S`, папка: `/D=C:\Папка`. |
| `WinDjView-2.1-Ukrainian-Setup.exe` | Лише мовний пакет для вже встановленого WinDjView 2.1 (x86 або x64): сам знаходить програму і додає `WinDjViewUA.dll`. |
| `WinDjViewUA.dll` (x64, x86) | Мовна DLL для ручного копіювання поруч із `WinDjView.exe`. |

Після встановлення мова вмикається в меню **Вигляд → Мова (Language) → Українська** (повний інсталятор може зробити це сам для поточного користувача). Програма завантажує мовну DLL лише якщо її версія (2.1) збігається з версією програми.

Повний інсталятор містить **офіційний `WinDjView.exe` 2.1 без змін** (не перекомпільований) і тому лише 64-бітний.

## Що змінено відносно оригінального репозиторію

Повідомлення про зміни (GNU GPL v2, §2a); дата змін — вересень 2026, повна історія — у `git log`.

| Шлях | Зміна |
|---|---|
| `windjview/Languages/Ukrainian/WinDjViewUA.rc` | Повністю новий переклад ресурсів (меню, діалоги, рядки, гарячі клавіші). Старий переклад 2007 року не покривав ~18% ресурсів, а програма 2.1 його не завантажувала. Ресурси синхронізовані з `Russian\WinDjViewRU.rc`. |
| `windjview/Languages/Ukrainian/resource.h` | Ідентифікатори синхронізовані з основним `windjview/resource.h`. |
| `windjview/Languages/Ukrainian/WinDjViewUA*.vcxproj[.filters]` | Проєкти були копіями російських (`AFX_TARG_RUS`, культура `0x0419`); виправлено на `AFX_TARG_UKR`, `0x0422`, додано відсутні bmp-ресурси. |
| `installer/` | Нове: скрипти NSIS для інсталяторів, скрипти збірки. |
| `docs/UKRAINIAN.md`, `.github/`, `.gitignore`, `.gitattributes`, `README.md` | Документація, CI, службові файли. |

## Збірка

### Linux / WSL / GitHub Actions (без Visual Studio)

```bash
sudo apt-get install mingw-w64 nsis python3-pefile
installer/tools/build.sh
```

Результат: `installer/build/{x64,x86}/WinDjViewUA.dll` і `installer/dist/*.exe` разом із `SHA256SUMS.txt`. Повний інсталятор збирається, лише якщо в `installer/bin/x64/` лежить офіційний `WinDjView.exe` (див. `installer/bin/README.txt`); за наявності ще й `installer/bin/x86/WinDjView.exe` інсталятор підтримуватиме і 32-бітну Windows.

### Windows (Visual Studio)

1. Відкрийте `windjview/WinDjView.15.sln` і зберіть проєкт **WinDjViewUA.15** (Release, x64 і/або Win32) — це дає `WinDjViewUA.dll`. Тут використовуються стандартні MFC-ресурси Visual Studio (`afxres.rc`).
2. Інсталятори (потрібен [NSIS 3.x](https://nsis.sourceforge.io/)), у папці `installer`:
   ```
   makensis /DDLL_DIR_X64=<папка з x64 DLL> /DDLL_DIR_X86=<папка з x86 DLL> WinDjView-UA-LangPack.nsi
   makensis /DDLL_DIR_X64=<папка з x64 DLL> WinDjView-Setup.nsi
   ```
   Повний інсталятор потребує `installer\bin\x64\WinDjView.exe` — або власної збірки з цього репозиторію (Release x64), або офіційного файлу.

## Технічні нотатки

Збірка на Linux (MinGW-w64) відрізняється від збірки у Visual Studio; ці відмінності закриті в `installer/tools/build_lang_dll.sh`:

- **Панелі інструментів.** `windres` записує ресурс `TOOLBAR` з 32-бітними ідентифікаторами, а MFC (`CToolBar::LoadToolBar`) читає 16-бітні — програма аварійно завершувалась при виборі мови. `tools/fix_toolbar.py` замінює блоки `TOOLBAR` на `RT_TOOLBAR` у форматі `rc.exe` (перевірено: байти збігаються з ресурсами офіційного exe).
- **Стандартні ресурси MFC.** У збірці без Visual Studio немає `afxres.rc`. `tools/afx_extra.rc` + `tools/afx_res/*.bin` — курсори, бітмапи, діалоги й таблиця прискорювачів MFC, скопійовані без змін з ресурсів офіційного `WinDjView.exe`; `tools/afx_strings_uk.py` — український переклад стандартних повідомлень MFC (діапазон `0xF000–0xF2EA`). У збірці Visual Studio цього не потрібно.
- **`tools/verify_dll.py`** перевіряє зібрану DLL: мова ресурсів `0x0422`, `FileVersion` = `IDS_CURRENT_VERSION`, формат панелей інструментів, повнота ідентифікаторів відносно російського `.rc`. Запускається з `build.sh` і в CI.

## Що перевірено

Перевірено на реальному офіційному `WinDjView.exe` 2.1 (x64) під Wine на Linux: запуск програми з українською мовою, відкриття DjVu-документа, меню, панель інструментів, вкладка «Мініатюри», діалоги «Налаштування», «Друк», «Про програму»; тихе встановлення/видалення обома інсталяторами (включно зі встановленням у задану папку, ярликами, записами реєстру).

**Не перевірено:** робота на справжній Windows 10/11; вигляд усіх діалогів (перевірено вибірково); 32-бітний варіант (DLL збирається й проходить `verify_dll.py`, але не запускалась); збірка в Visual Studio (і `WinDjView.exe`, і `WinDjViewUA.15`); робота workflow GitHub Actions (кроки перевірені локально на Ubuntu, на GitHub не запускались). У чотирьох рідкісних стандартних діалогах MFC (нове вікно, переривання друку, панель попереднього перегляду) текст залишився англійським.
